这份《用户手册》确保你在搭建好系统后，能像专业编辑一样管理自己的知识库。它包含了从手机端写作、图片处理到后台回滚的所有实操细节。

---

### 1. 写作端的初始化配置

在开始创作前，请确保你的 **Obsidian**（手机/电脑端）已按此标准调教：

* **同步插件配置 (Remotely Save)**：
* **服务商**：选择 `S3 Compliant Storage`。
* **Endpoint (关键)**：请填写你的 **自定义域名**（例如 `https://sync.yourdomain.com`），而非 Cloudflare 默认的长串地址。
* **Bucket 名称**：填写你在 R2 创建的桶名。
* **连接测试**：点击“Check”，确保国内网络环境下无需代理也能秒连。


* **附件管理规范**：
* 进入 `Settings -> Files & Links`。
* `Default location for new attachments`：选择 `Subfolder under current folder`。
* `Subfolder name`：统一填入 `attachments`。
* **禁止 WikiLinks**：关闭 `Use [[Wikilinks]]`，确保图片以标准 Markdown 语法 `![](./attachments/xxx.png)` 插入，以便 GitHub Actions 识别并压缩。



### 2. 标准博文创作规范

为了触发系统的高级功能（如自动海报、Notion 视图），请遵循以下 YAML 模板：

* **模板使用**：点击 Obsidian 的“插入模板”按钮。
* **核心字段说明**：
```yaml
---
title: 文章标题
date: 2026-03-12 10:00
updated: 2026-03-12 10:00
status: reading    # 可选值: drafting(草稿), reading(在读), done(已读)
rating: 5          # 评分 (1-5)，将触发网页端星星显示
cover: auto        # 设为 auto，系统将自动根据标题生成封面图
tags: [技术, 生活]
---

```


* **发布操作**：
1. 写完文章后，点击 Obsidian 侧边栏的“同步”按钮。
2. **“15秒法则”**：点击同步后即可关闭手机。系统会等待 15 秒（防抖）并在 15 秒冷却后自动触发云端构建。



### 3. 多媒体资源的处理

* **图片插入**：直接将图片粘贴到 Obsidian 即可。
* **自动处理**：你无需手动裁剪。当你同步到 R2 后，GitHub Actions 会自动执行以下任务：
1. 将原始大图（JPG/PNG）压缩转换为 **WebP** 格式以节省流量。
2. 自动将网页中的图片链接指向压缩后的版本。

接上文，这是**《用户手册》**的**第二部分**。这部分专注于你在浏览器端的“管理视角”，包括如何救急、如何监控系统健康以及如何处理版本冲突。


### 4. 网页后台管理 (Decap CMS)

当你不在电脑前，或者需要快速调整博文状态时使用。

* **访问地址**：`https://yourblog.com/admin`。
* **登录流程**：
1. 由于开启了 **Cloudflare Zero Trust**，你会先看到一个验证页面。
2. 输入你的授权邮箱获取验证码，或输入预设密码。
3. 验证通过后，直接进入管理后台（无需再点 GitHub 登录，中转 Worker 已自动代签）。


* **在线编辑**：
* 在后台修改文字或状态后点击“Save”。
* **反向同步**：网页端的修改会自动通过 GitHub Action 推回你的 R2 存储桶，确保手机 Obsidian 下次同步时能拿到最新的改动。



### 5. 版本回滚与“后悔药”操作

当你发现误删了内容，或者想找回某天下午的博文状态时：

* **进入版本管理页**：在后台导航栏点击“Version Management”。
* **识别版本信息**：
* 页面会显示历史快照列表，每行都会标注：**[快照时间] - [包含博文数] - [版本来源]**。
* 例如：`2026-03-12 14:00 源自 2026-03-11 10:00`。


* **内容预览**：在执行恢复前，点击快照中的具体博文标题，界面会弹窗显示该版本的内容。
* **执行回滚**：点击“Restore to this version”。
* **底层动作**：系统会自动从 R2 的历史版本中提取文件，覆盖当前最新文件，并触发全站重新构建。



### 6. 容量监控与维护

为了保证 R2 存储不超支并保持系统轻量：

* **容量仪表盘**：后台顶部会有一个实时进度条。
* **绿色**：存储健康。
* **红色**：接近阈值（如超过 8GB），建议手动执行清理。


* **手动清理触发**：
* 在设置页点击“Run Cleanup Now”。
* 系统会立即按照你设定的策略（如：只保留最近 50 个版本）抹除 R2 中的冗余历史。



### 7. 异常处理与常见问题

* **15秒内多次保存了怎么办？**
* 系统会自动丢弃前几次信号，只保留最后一次保存后的 15 秒触发构建，不会产生多次构建浪费资源。


* **国内同步转圈圈？**
* 请检查手机端 Endpoint 是否写成了自定义域名 `sync.xxx.com`。


* **网页没更新？**
* 去 GitHub Action 查看最后一次构建是否报错。通常是图片格式损坏或 YAML 语法错误（如缺少空格）。
